# 批次五设计稿：测试体系与场景矩阵

> 定位：本稿是批次五（测试基础设施 + 场景矩阵）的施工图，由队长起草、用户已就其骨架给出口径（三层职责 + 因子覆盖要全）。
> 与既有文档的关系：类文档遵循六段范式；本稿是阶段级设计稿，配套附录含"测试踩坑清单"（24 条）与历史事故索引。
> 本稿不含代码，只定义"写什么、按什么判据、怎么算过"。

## 1. 目标与验收标准

**目标（一句话）**：把"能测的"变成"测得到的" —— 建立**三层测试体系**（单元 / 集成 / 端到端）、**共用判据工具**与**全场景演示矩阵**，使"跨后端不一致、朝向/镜像、更新链路、连续帧稳定性、控制流走错分支"这五类缺陷在合并前被抓住；并把已踩过的坑逐条固化成约定与断言。

**批次整体验收**：

1. 三层职责清晰落地（见 §3），每层有明确的驱动方式（边界数据 / 操作序列 / 场景命令）。
2. 八类内容分区（见 §4）各有归属层与至少一条**承重判据**（哪条断言负责抓哪类缺陷，写进映射表）。
3. **因子矩阵 + 覆盖地图**（见 §5）可生成：每个因子取值都有用例覆盖，缺口自动暴露。
4. 附录 A 的 24 条踩坑**逐条**有对应约定或断言（映射见 §6）。
5. 端到端渠道（见 §7）对用户可用：一个场景一条命令、一键出图、配对照表与基线。
6. 所有新增断言都在**已登记进构建**的测试文件里，且每条都有判别力证据（变异反证 + 逐字节复原）。
7. 每个工作步仍走"实现 → 独立审查（含变异反证）→ 过审"闭环。

## 3. 三层职责

| 层 | 驱动方式 | 判据形态 | 跑在哪 |
|---|---|---|---|
| **单元** | **边界数据表**：每个类的关键函数 × 各种边界输入 | 逐格断言（纯数学/契约，不画屏幕） | `Test/unit`（offscreen，快） |
| **集成** | **操作序列**：用户会做的各种操作及其组合 | 每一步"应有反馈"，**一路查到像素**；含状态/控制流转移 | `Test/integration`（含真 GL，需 wayland） |
| **端到端** | **场景命令**：一个场景一条命令，一键出图 | 给用户的目验渠道 + 产物基线回归 | `Test/demos` + 出图脚本 |

### 3.1 单元层：关键函数 × 边界数据（示例清单）

- **轴的范围与刻度**：对称 / 非对称 / 跨零 / 极窄 / 极宽 / 单点 / 退化（min=max）/ NaN、Inf / 超大与超小量级 / tickCount 极小与极大
- **相机窗口运算**：三种 fit 模式（拉伸 / 适配 / 裁剪）× 缩放系数 × 退化尺寸 × 居中与偏心
- **投影正反变换**：各投影的奇点、边界角度、非线性区的往返误差
- **标签锚点**：三级优先级的缺失/越界/NaN 组合；组尾图元四种类型
- **场景与图元容器**：空场景 / 单图元 / 引用越界 / 重复提交
- **脏指纹**：字段表逐字段"改一次必须触发重收集"

### 3.2 集成层：操作序列 × 应有反馈 × 查到像素

**(a) 交互操作序列**（用户会干的事）

- resize：连续、极端尺寸、缩放因子变化、最大化/最小化
- **元素添加顺序**：先层后轴 / 先轴后层 / 中途加删轴 / 中途加删层 / 切后端前后加轴 / 重复添加同一对象
- 后端切换：CPU↔GL 往返（含切换时正在拖动）
- 交互组合：拖动后再缩放、滚轮后再拖动、fit 触发后手动改轴范围、改刻度数后立刻拖动
- 交叉：resize 后立刻拖动、拖动中 resize

**(b) 状态与控制流**（分支走对没有；本项独立成节，理由是"控制逻辑 ≠ 数学逻辑"）

- 脏标记三条通路（视图 / 内容 / 数据）与"不变化就不重收集"
- 方向状态：数值侧 fit ↔ 相机侧反算的相互覆盖、防回环抑制深度归零后不得回流
- 门控：交互开关、三维自动适配开关、可见性开关、退化范围早退
- 资源状态：上下文重建后缓存是否仍有效（与 GL 资源生命周期相关）

**(c) 判据一律查到像素**：每步抓图，断言"该变的地方变了、不该变的地方一点没变"（例如"绘图区内变了、边框带没变"），而不是只看计数器或标志位。

### 3.3 端到端层（给用户的验证渠道）

- 场景命令：`QChartDemo <场景> <cpu|gl> [dpr]`；`QCHART_DEMO_SHOT=1` 一键出图；命名规范统一。
- **对照表**：哪张图、什么参数、守护哪条结论、什么变化算正常（有意变更登记在此）。
- **一键全跑脚本**：跑完输出一个图片目录 + 检查清单，用户打开目录即可逐张目验。

## 5. 因子矩阵与覆盖地图（"分类要全"的可数化）

每个测试用例/场景必须申报自己覆盖的因子格子；由此生成覆盖地图，缺口自动暴露。

| 因子 | 取值 |
|---|---|
| 维度 | 2D / 3D |
| 投影 | 直角二维 / 极坐标 / 函数二维 / 直角三维 / 球 / 柱 / 函数三维 / **插值（投影切换动画中间态）** |
| 网格模式 | 二维：开/关、脊标注三态；三维：面线 / 盒 / 晶格 |
| 后端 | CPU / GL |
| fit 模式 | 拉伸 / 适配 / 裁剪 × 缩放系数 |
| 缩放因子 | 1.0 / 1.5 / 2.0 |
| 交互 | 无 / 拖动 / 滚轮 / 轨道 / 推拉 / 尺寸变化 |
| 容器 | 单层 / 多层 / 多 widget / 后端切换 |
| 数据边界 | 对称 / 非对称 / 跨零 / 退化 / 单点 / 极大极小 / NaN |
| 帧序 | 单帧 / 连续 N 帧（稳定性） |

**覆盖地图产出**：因子取值 → 覆盖它的用例清单；未覆盖格子单列成"缺口表"，作为派活依据。历史事故标在格子上（②镜像=后端×方向；③a=标注×连续帧；①=容器×更新传播），新 bug 也能立刻定位"哪个格子还没人守"。

## 6. 硬性约定（12 条，均由真实事故换来）

| # | 约定 | 来源事故 |
|---|---|---|
| 1 | 夹具必须**非对称**，断言里显式检查"刻度集不关于视图中心对称" | ②镜像被对称 demo 掩护 |
| 2 | 夹具形态必须与生产路径一致（或用生产 helper 组装） | drawAtEdge 取向错配 |
| 3 | 每类缺陷标注**唯一承重判据**，并说明哪些只是旁证（警惕 `grab()` 这类自强迫 API 掩盖调度缺陷） | t78 F1 |
| 4 | 位置/朝向类判据用"同一特征同一像素位置 ±1px"；禁止"有墨即可 / 排序后匹配 / 计数>0" | ②长期漏检 |
| 5 | 标签类判据必须**像素级**，不得只看 `visible` 标志 | ③a（visible 为 true 却实画 0） |
| 6 | 期望用**字面常量**；变异反证 + sha256 逐字节复原；临时改动必须声明 | 4f 自证式期望 |
| 7 | 断言只准写进**已登记进构建**的文件；新增"登记一致性检查"用例（`tests/*.cpp` 必须已登记或在 legacy 白名单） | 断言写进未构建文件 |
| 8 | 测试运行侧**关闭 QtTest 消息上限**（`-maxwarnings 0`），并把"断言不得因消息上限被跳过"写成约定 | wayland 静默截断 |
| 9 | GL 用例**一等公民化**：注册 wayland 版 ctest 目标（带标签），不再依赖手工命令；无 GL 环境的回归须注明 | 历史手工跑法、t78 F2 |
| 10 | 诊断/探针结论必须**三路交叉**（仓内断言 + 聚合像素 + 逐组点名）且走**真实窗口路径** | t70 探针盲区、t77 首版探针 |
| 11 | 产物对账规范：背靠背 A/B/A + 显式 diff + 取景归一；**产物不能守护镜像/朝向类回归** | 多处 |
| 12 | 计数类断言必须给**构成**；烟雾级阈值一律改**结构断言** | 4i、test_axes3d_gl |

## 附录 A：测试踩坑清单（24 条）

**一、夹具类**
1. 夹具取向与生产相反（drawAtEdge）：测试喂的矩形方向与生产组装相反 ⇒ 反向读取在测试里恰好正确。
2. 对称夹具让镜像伪装成"没变化"：demo ±10 + 等间距刻度 ⇒ 镜像后网格集合与原来重合，15 张产物逐字节不变。
3. 夹具参数把缺陷掩盖：症状②夹片刻度关于中心对称 ⇒ 探针判"复现不出来"。

**二、判据类**
4. 只看标志不看像素：③a 旧实现丢整组时 `label.visible` 仍为 true。
5. "有墨即可 / 排序后匹配 / 计数>0"：②、① 全能穿过这类弱判据。
6. 自强迫 API 掩盖调度缺陷：`grab()` 强制重绘 ⇒ 变异下像素与 md5 与修复态全同，只有重绘计数会红（t78 F1）。
7. 期望由生产代码反推：`1.0/1.15` 之类 ⇒ 实现错、期望一起错（4f）。

**三、运行与构建面**
8. 断言写进不参与构建的文件：25 个单元测试文件只有 5 个在跑；legacy 文件引用已删接口（语法检查 28 错）。
9. QtTest 消息上限静默截断：上限 2000，被前序用例耗掉 1739 ⇒ 后续断言被跳过，"0 failed"是假绿。
10. offscreen 平台无真实 GL：GL 用例被跳过；①类回归"无 GL 环境抓不到"。

**四、工具与证据自身**
11. 用裸渲染器代替真实窗口路径：t70 探针判"上下反向不可复现"是错的。
12. 探针取样窗口假设不成立：首版探针 ±22px 窗口找不到字形簇（墨迹质心与锚点可差 464.7px）⇒ 假数字。
13. 产物取景不同还逐像素比：窗口级 1084×856 vs 整屏 2160×1440；产物还受窗口缩放状态影响。
14. 临时变异/插桩不留痕：后来定为"必须声明 + sha256 复原"。

**五、平台与环境**
15. Debug 构建被当成性能结论（DLL 带 `d`）。
16. DPR 放大内容型成本：7.3ms/帧（DPR1）→ 25.9ms/帧（DPR1.5）。
17. 软件 GL 与真实显卡墨迹量差异大 ⇒ 别拿墨迹数量当阈值。
18. 跨平台差异要三档排除驱动论（`QT_OPENGL=desktop|angle|software`）。

**六、流程与纪律**
19. 断言必须能变红（修复前状态验证），否则不算守护（4c 被打回）。
20. 计数断言必须给构成（几条脊×几刻度×几点）（4i）。
21. engineer 只做轻量自检，深度审查独立；问题按"严重度/部位/修复路径"写。
22. 一次改动一次尝试；同文件必须串行。
23. 构建/实跑取锁串行（沙箱 PID 隔离使 `pgrep` 互斥失效，曾因此 OOM 两次）。
24. 越界必须声明 + 给哈希 + 说明必要性（t73）。
